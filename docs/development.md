# Development

## Running the tests

The tests are split by what they need:

```bash
# Configuration, reductions and file formats, with the scientific libraries blocked:
python tools/run_core_tests.py tests -q

# Everything that runs on a CPU:
python tools/run_backend_tests.py tests -q -m 'not xtx_gpu and not xtx_multi_gpu'

# Tests that need one GPU, and tests that need two:
CUDA_VISIBLE_DEVICES=0 JAX_ENABLE_X64=1 python tools/run_backend_tests.py \
    --require-gpu --numba-jit enabled tests -q -m 'xtx_gpu and not xtx_multi_gpu'
CUDA_VISIBLE_DEVICES=0,1 JAX_ENABLE_X64=1 python tools/run_backend_tests.py \
    --require-gpu --numba-jit enabled tests -q -m xtx_multi_gpu
```

The core runner checks that no scientific library was imported, which keeps
configuration handling and result loading usable on machines without them. The backend
runner sets up the AutoArray configuration the tests expect. Batch tests need Linux.

Tests are grouped by package under `tests/`. Expected values come from independent
calculations (closed-form lensing and photometry, analytic PSFs), from fixtures of the
RASTI code, or from comparisons between the reference and JAX engines.

## Paper parity

`tests/parity/` checks the forecast, optics and nonlinear likelihood against fixtures
computed with the RASTI code for five test scenes. The reference engine must reproduce
the RASTI reference-engine values bit for bit, and the JAX engine on a GPU must reproduce
the RASTI GPU values bit for bit. The JAX engine on a CPU must agree to a few parts per
million. The fixtures were made by `tests/scripts/generate_paper_parity.py`,
which runs the tagged RASTI code. To check that the committed inputs still match:

```bash
python tests/scripts/generate_paper_parity.py --inputs-only --out /path/to/new-inputs
```

## Writing tests

- Test behaviour through the public interface, with the real scientific libraries.
- Take expected values from an independent source, not from the code under test.
- Extend an existing test or parameter table before adding a new file.
- A test that needs a GPU is marked `xtx_gpu`; one that needs two is marked `xtx_multi_gpu`.

## Building the documentation

The documentation is built with Sphinx, MyST and the Furo theme. The API reference is
generated by AutoAPI from the source code without importing it, so the scientific
libraries are not needed. In a separate Python 3.11 environment:

```bash
python -m pip install -r docs/requirements.txt .
python -m sphinx -W --keep-going -b html docs docs/_build/html
```

Open `docs/_build/html/index.html`. `-W` turns warnings into errors.

The configuration reference is generated from the code. When a configuration table
changes, regenerate `docs/CONFIG.md`; the build fails if it is out of date:

```bash
python -m hwoslaps reference > docs/CONFIG.md
```

The figure on the quickstart page is made by `docs/_scripts/quickstart_figure.py`, run
from the repository root in the scientific environment.

`.readthedocs.yaml` configures a Read the Docs build with the same settings, and
`.github/workflows/docs.yml` builds the HTML on pushes and pull requests that touch the
documentation or source.
